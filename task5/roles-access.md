# Модель изоляции данных

Данные изолируются на уровне БД:

- У каждого партнёра свой `tenant_id`
- У каждого `tenant_id` своя БД, приложение маршрутизирует запросы в нужную БД по `tenant_id`
- IAM / SSO - токен содержит `tenant_id` и `roles`

## Роли и доступ к данным

Основные принципы:

- Все роли ограничены своим тенантом - пользователь видит данные только своего `tenant_id`
- `tenant_id` и `roles` содержатся в токене
- Мультитенантные роли имеются только у "спецальных" юзеров, типа админов / разработчиков

| Роль | Кому выдаётся | Доступ к данным | Права на операции |
|---|---|---|---|
| role_passenger | Пассажир | Только свои данные в рамках tenant (свои поездки / платежи / профиль) | Создание / отмена заказа, просмотр истории, оплата |
| role_driver | Водитель | Только свои данные в рамках tenant | Принятие / завершение заказа, статусы, просмотр начислений |
| role_manager | Корпоративный менеджер | Данные своей компании (в рамках tenant) | Создание поездок для сотрудников, отчёты по компании |
| role_buh | Бухгалтерия | Финансовые данные (в рамках tenant), без доступа к персональным данным сверх нужного | Просмотр выплат, выгрузка отчётов |
| role_support | Агенты поддержки | Ограниченный read-only + операции поддержки | Просмотр поездок, ручные корректировки (по политике) |
| role_admin | Админ | Полный доступ | Полный доступ для отладки / мониторинга |
